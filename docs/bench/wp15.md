# Bench sheet — WP15: the camera node

For João, on the XPS 15 9570 (GTX 1050 Ti, 6 cores) and the ThinkPad T14 Gen 1
(Intel iGPU, 4 cores), Mon 16 / Tue 17 Nov, before the race on Sat 21.
Decisions: [ADR 0023](../adr/0023-camera-node.md). Write each result next to
its step (date, laptop, what you saw); a step that fails: what happened, and
the node's log (its page, or `%ProgramData%\BajaCameraNode\logs`).

## 0. Install

- [ ] Run `BajaCameraNode-<version>.exe` on the XPS (firewall option ticked).
      The *Baja camera node* service runs; `http://localhost:8891/` shows the
      node's page, in red "No token set".
- [ ] On the page: name the node, set a token, Save. Reload: the page asks for
      the token.

## 1. The video bench (node mode only)

- [ ] Stop the *Baja camera node* service first (it would hold the cameras),
      plug in both S600s, and in a terminal:
      `"C:\Program Files\BajaCameraNode\python\python.exe" -m baja_studio.node.video.bench`
      It finds the bundled ffmpeg by itself. It prints the cameras and their
      modes and which encoders work, then runs one camera and then two for
      60 s each, then 20 s passes with each hardware MJPEG decoder. Note per
      camera: fps in and out, dropped frames, encoder, bitrate, window apply
      time and move latency, and the laptop's CPU %. Same on the ThinkPad.
- [ ] If a camera is missing or its modes look wrong, run it again with
      `--raw` and keep what ffmpeg prints (the device and mode listings).
- [ ] If a hardware decoder pass worked and saved CPU, set *MJPEG decoder*
      to it for that laptop's cameras on the node's page (step 2).
- [ ] Start the service again. Decide per laptop: node mode, or OBS mode
      (step 1b).

## 1b. OBS mode instead (if node mode is too heavy)

- [ ] OBS on the laptop as in the WP13 runbook (page 24): each S600 a source,
      streaming to its Feeds URL. On the node's page: camera → *Video done
      by: OBS on this laptop*, port and password, **Test connection**
      (connected), **List OBS sources**, pick the source, **Create filter** if
      it has none, Save. Status ok, OBS connected.
- [ ] Optional: an uncropped view of the camera in OBS (a Source Clone without
      filters) as *Uncropped preview source*: the studio's preview then shows
      the whole picture instead of piecing it together.

## 2. Feeds

- [ ] Studio, **Feeds**: a feed per laptop camera. Copy each SRT URL into the
      node's page (*Output URL*), Save. The feeds go live on the Feeds page.
- [ ] The node's page shows `Sends to srt://<studio>:8890?streamid=***`, never
      the password.

## 3. Add the node to the studio

- [ ] Studio, **Agents**: add the laptop (address, port **8891**, the token).
      It goes ok; its cameras appear as crop cameras.
- [ ] Studio, **Camera setup**: an agent camera for each (agent, camera id).
      **Feeds** → *Add to OBS* for each feed.

## 4. Driving

- [ ] Web stick, keys and joystick on each camera: smooth on stream? Note any
      stutter, and the move latency you feel.
- [ ] Zoom to 2× (no upscaling: 1080p from 4K); the preview shows the whole
      frame with the window on it; click-to-centre.
- [ ] Presets: store 1–3 (from the page, the joystick's Call buttons, the
      D200), recall them. They are kept in the studio (Camera setup).
- [ ] Hold a direction and pull the studio's network cable: the window stops
      within the ttl (0.3 s).

## 5. Image controls

- [ ] Studio, **Image**: exposure, white balance, focus on each node camera
      while it streams (both modes). Values take; the picture changes.
- [ ] Unplug a camera and plug it back: the settings come back by themselves.

## 6. Robustness

- [ ] Unplug one camera: its status says why, the other camera and the API
      carry on; plug it back: it recovers, same window.
- [ ] Pull the laptop's network cable for 20 s: feeds and agent come back.
- [ ] Restart the *Baja camera node* service; then reboot the laptop and do not
      log in: the node answers (studio's Agents page ok), cameras ok.
- [ ] Switch a camera's mode (node ↔ OBS) on the page and Save: no node
      restart; the camera stays on the studio's pages.

## 7. With the MV app on the same laptop (if planned)

- [ ] Both running (the MV app's agent on 8890, the node on 8891): CPU, and the
      tracker's fps.
