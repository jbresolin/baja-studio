# WP14 bench session: Feeds (MediaMTX) for the drone and remote cameras

The checklist is §6 of the WP14 brief (Plane page "23 — WP14 brief"). Record
the results in a comment on **LIVESTACK-65**. Decisions are in
[ADR 0022](../adr/0022-feeds-mediamtx.md).

Set-up: the streaming PC with this version installed (firewall option
ticked), OBS running and connected to playout (the playout page says
*connected*), a scene to put feeds in that is **not** named like a feed's
label (OBS refuses two sources with the same name, scenes included). A phone
with an RTMP app (e.g. *Larix Broadcaster*) or the drone's controller app,
and a laptop with OBS 30+, both on the studio's network. A clock on screen
for delays (a phone's stopwatch filmed by the drone, or
`time.is` on the laptop).

| # | Step | Expected | Result |
| --- | --- | --- | --- |
| 1 | Open **Feeds** in the top bar | "MediaMTX v1.21.3 running (BajaStudioFeeds…)"; the home page's Feeds card is **ok**; Readiness has the four feeds checks | |
| 2 | Add feed: name `drone`, label `Drone`, kind drone | A card appears, **waiting**, with `rtmp://<PC address>:1935/drone` first and a Copy button | |
| 3 | From the phone app (or drone controller), push RTMP to that URL | Within 2–4 s the card is **live**: RTMP, the resolution, a bitrate, "0 reading" | |
| 4 | Card → **Add to OBS** → pick the scene → **Add "Drone"** | "Added…"; in OBS a *Media Source* "Drone" in that scene, picture and sound playing; the card shows "1 reading" | |
| 5 | Film the clock with the phone/drone; compare with OBS's preview | Note the delay (sender to OBS) | |
| 6 | Stop the push for 10 s, start it again | Card goes **waiting**, then **live**; OBS's picture comes back by itself within a few seconds, nothing touched in OBS | |
| 7 | Press **Add to OBS** again for the drone | Refused: "OBS already has a source named 'Drone'…"; the existing source is unchanged | |
| 8 | Add feed `laptop1` (label `Laptop 1`, kind laptop). On the laptop's OBS: Settings → Stream → Service *Custom*, Server = the shown SRT URL, Stream key empty; Start Streaming | Card **live**: SRT, 1920×1080 (or 3840×1080 for two cameras); Add to OBS as in 4 | |
| 9 | In OBS's log on the laptop (Help → Log files), find the SRT latency it used | 200 ms (the URL says `latency=200000`, microseconds); note if OBS read it otherwise | |
| 10 | Pull the laptop's network cable for 20 s, plug it back | Card **waiting**, then **live** again without touching OBS on either PC (the laptop's OBS reconnects; set its *Auto-Reconnect* on) | |
| 11 | Restart the **Baja Studio** service (Services app, or the tray's restart) while a feed is live | OBS's picture does not drop; the Feeds page comes back with the feed still live | |
| 12 | Edit `laptop1` → *record to disk* → Save | Within a few seconds, a folder `feeds-recordings\laptop1\` in the data folder with an `.mp4` growing; the page shows the free space | |
| 13 | Edit `drone` → password `drone-pw` → Save; push without it | Refused (card stays waiting); push to the URL with `?user=drone&pass=drone-pw`: **live**. Other feeds did not drop when the password was saved | |
| 14 | In the drone app, type `dorne` instead of `drone` | The page shows "Refused (unknown feed name): dorne at …" | |
| 15 | Change *Rtmp Port* to 8888 in the settings below the cards | Refused: "rtmp_port 8888 is used by the studio" | |
| 16 | Start another RTMP server on 1940 (or VLC streaming there), set *Rtmp Port* 1940 | Refused, naming the program on 1940; MediaMTX keeps running on 1935, the drone still live | |
| 17 | Stop **Baja Studio feeds** in the Services app | Within 2 s the page says MediaMTX is not answering, the service is stopped, with its last log lines; start it again: everything back | |
| 18 | Open the Feeds page on a phone through `studio.bajasaebrasil.net` | Cards readable; Copy works (HTTPS) | |

Notes for the record: the delays measured in 5 and 8 (RTMP and SRT, with
OBS reading RTSP over TCP); whether `restart_on_activate` (the media source
reopens when its scene is shown) is wanted for live feeds or should be off;
CPU of MediaMTX in Task Manager with two feeds live (and one recording).
