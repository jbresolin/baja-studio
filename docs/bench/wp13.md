# WP13 bench session: crop cameras in a remote OBS

The checklist is §6 of the WP13 brief (Plane page "22 — WP13 brief"). Record
the results in a comment on **LIVESTACK-64**. Decisions are in
[ADR 0021](../adr/0021-crop-cameras-in-a-remote-obs.md); everything ADR 0020
(and [the WP6b bench](wp6b.md)) checked for a local crop camera should hold
for a remote one.

Set-up on the **laptop**: OBS 30 or newer with obs-websocket on (Tools →
WebSocket Server Settings: *Enable WebSocket server* ticked, port **4455**,
*Enable Authentication* ticked with a password). Windows firewall allowing
TCP 4455 on private networks (Windows Defender Firewall → Advanced settings →
Inbound Rules → New Rule → Port → TCP 4455 → Allow → Private; or accept
OBS's own prompt for private networks). The laptop's network set to
*Private*. A 4K webcam in OBS as a *Video Capture Device* at **3840x2160**
(Resolution/FPS type: Custom), in a scene with its transform set to
**Stretch to bounds** of the canvas. A source projector open for it.
Note the laptop's address (`ipconfig`).

On the **studio PC**: the studio running, with or without playout's own OBS
(a remote crop camera does not need it).

| # | Step | Expected | Result |
| --- | --- | --- | --- |
| 1 | Camera setup → Add camera: driver *OBS crop*; *OBS* → **Remote OBS**; address, port 4455, password; **Test connection** | "✓ connected to OBS <version> (obs-websocket <version>) at <address>:4455"; the *OBS source* list now shows the laptop's sources | |
| 2 | Pick the 4K webcam, Id `lap1-a`, Save | Camera listed as "OBS crop <source> @ <address>:4455"; on the Cameras page **degraded** "… has no filter 'Baja crop': use Create filter on Camera setup" | |
| 3 | Edit it → **Create filter** | The laptop's OBS shows a *Crop/Pad* filter "Baja crop" on the webcam (Relative ticked, all 0); the camera turns **ok**; the projector still shows the whole picture | |
| 4 | Hold *Zoom in*, then the web stick and arrow keys in all directions, then let go | The laptop's projector zooms and pans smoothly (note any judder at 25 Hz over the link); stops at once on release; 2.0× at most | |
| 5 | **Shift+2**, move away, **2**; click the preview near an edge | Jumps back to the stored window; the window centres on the click | |
| 6 | The preview on the Cameras page and on a phone | About one picture a second; the window outline follows the stick | |
| 7 | In the laptop's OBS, add a second 4K webcam (Video Capture Device, 3840x2160, Stretch to bounds), then a second camera `lap1-b` on it (same address and password), Create filter | Both **ok**; the studio still has **one** connection to the laptop (Task Manager → Performance → *Open Resource Monitor* → Network → TCP Connections: one to port 4455 from the studio); moving one never moves the other | |
| 8 | Unplug the laptop's network cable for about 20 s, then plug it back | Within a few seconds both cameras **offline** "OBS at <address>:4455 …" (the same words on both); after plugging back both **ok** by themselves, at the windows they had (nothing moves) | |
| 9 | Edit `lap1-a`, type a wrong password, Save | Both cameras **degraded** "OBS at … refused the password …"; Camera setup on `lap1-b` says `lap1-a` was saved later with another password. Put the right password back on `lap1-a`: both **ok** without restarting anything | |
| 10 | Test connection with a wrong password, then with a wrong address | "✗ OBS at … refused the password"; "✗ OBS at … unreachable: …" (note how long the unreachable answer takes) | |
| 11 | Close the laptop's OBS; open it again | Both cameras **offline** naming the laptop, then **ok** by themselves with their windows kept | |
| 12 | While the link is down (step 8), move the studio PC's own crop camera (if one is set up) and open its preview | It moves and previews as usual: a missing laptop slows nothing else | |
| 13 | Set the camera's *OBS* back to **This PC** and Save | The studio closes its connection to the laptop (Resource Monitor); the camera now follows playout's OBS | |
| 14 | On the laptop: Task Manager CPU and OBS's Stats dock with one 4K source, then two | Note CPU, GPU, "frames missed due to rendering lag" and "skipped frames due to encoding lag" with one and with two 4K sources | |

Notes for the record: the laptop's OBS and obs-websocket versions; the link
(cable, Airmax); how long a move takes to show on the laptop's projector
compared with a local crop camera; whether previews feel slower over the
radio.
