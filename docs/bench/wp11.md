# WP11 bench session: the rehearsal rig

The checklist is §4 of the WP11 brief (Plane page "17 — WP11 brief").
Record the results in a comment on **LIVESTACK-59**.

No hardware at all: the rig starts every fake and a second studio on port
**8889**, with its own data in `%LOCALAPPDATA%\BajaStudioRig`, apart from
your own studio. Run each command from `server\` in the virtual environment.
ffmpeg must be on PATH (or run from an installed studio's folder) for the
demo clips.

## 1. Fresh start, everything green

1. Fresh venv (`pip install -e "server[dev]"`), then:

       python -m baja_studio.rig --reset

   The first run makes 12 demo clips (about a minute), then prints the fakes
   and their ports, the seed (`fake OBS timing seed: 2026`) and
   **Open http://127.0.0.1:8889**.
2. The browser opens two tabs by itself (`--open`, on by default): the home
   page, and a **hosts screen for seats 1-4** (`/hosts?seats=1,2,3,4`),
   which counts for the readiness check without tapping its seat picker.
   Keep that tab open. If no browser opens, the terminal says which address
   to open by hand.
3. Home: every module card **ok** (gateway **stopped**: it is off in the rig).
4. **Readiness → Run all checks**: **READY, 0 warnings**. Close the hosts
   tab and run again: one warning, "no hosts screen is open" (it comes back
   within a few seconds of reopening it).

`--no-open` skips the tabs; the terminal then prints both addresses.

## 2. Playout bench against the rig

Run steps 3-6 of the WP5c bench (§5 of its brief; `docs/bench/wp5c.md` → Steps) on
`http://127.0.0.1:8889/playout`. The library has the delivered clips
(enduro, suspensao, aceleracao; one vertical, some with a tone), the
**Patrocinadores** group, and `extra-take.mp4`, which no manifest entry
matches. The fake OBS takes OBS-like random time to open and seek (seed
printed at start; `--seed N` replays a run, `--fast-obs` turns it off).

## 3. Agent drops out (`flaky-agent`)

    python -m baja_studio.rig --scenario flaky-agent

Open **Cameras**. The terminal prints each step as it happens.

- At **30 s** agent 2 (rig-laptop-b) goes silent: its cameras turn
  **offline** about 5 s later, and `rig-b-cam1` is driven **directly** (its
  fake VISCA camera) 10 s after that.
- At **45 s** it answers again: the cameras come back through the agent and
  resync. A request that was waiting may answer up to 5 s late.

## 4. Mixer drops out (`mixer-drop`)

    python -m baja_studio.rig --scenario mixer-drop

Open **Audio**, and keep the hosts tab in view (its audio card).

- At **20 s** the XR18 stops answering: Audio and the hosts' audio card show
  the mixer **offline** after 5 s.
- At **30 s** it answers again, but loses about 30 % of the time for 30 s:
  it may flicker offline and back. From **60 s** it is steady and both
  pages are back.

Two more scenarios for the readiness warnings: `post-fader-tap` (at 20 s
HOST 1's send to its in-ears is taken after the fader: the next run warns
"Linked sends are pre-fader") and `lr-assign-silent` (the mixer never
reports channel 1's LR assign: "Hosts can be taken off air" warns).

## 5. Nothing left running

Press **Ctrl+C** in the rig's terminal. It prints `stopping ...` and then
`stopped: no fake or studio left running`. In Task Manager → Details, no
`python.exe` from the rig is left (the rig, seven fakes, the studio and its
two helper processes: eleven in all while it runs). Start it again at once:
it comes up (no port is left in use).
